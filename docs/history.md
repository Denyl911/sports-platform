# How this project was built

Not what shipped, which is [`CHANGELOG.md`](../CHANGELOG.md), and not what is coming, which is [`todo.md`](./todo.md). This file is what was *learned*: the lessons that would change what somebody does next time, each with the case that taught it and a link to where the full account lives. The binding decisions are in [`adr/`](./adr/), the questions answered in [`decided.md`](./decided.md).

**How an entry is written.** One lesson, one paragraph: the lesson in bold, then the case in a sentence or two, then the link. It goes under the theme it teaches, not under the release or the round that found it, and a lesson learned a second time adds its case to the entry that is already here rather than opening a new one. No release narrative, no list of what a round fixed, no story an ADR already tells. If an entry would not change what somebody does next time, it does not belong here.

## Themes

- **What is measured** — numbers and how they were taken.
- **Measuring** — ways the instrument lied and how it was caught.
- **Where it came from** — what the architecture was modelled on, and what changed that mind.
- **Health** — failures of the gate and of the ground it stands on, caught by actually running things.

## What is measured
**The shadcn CLI vendoring a foreign registry drops files where it wants and rewrites deps — realign by hand after every add.** `bunx shadcn add "@react-bits/…" --cwd packages/ui` landed the components in `src/components/` instead of the `ui` alias (`bits/`) the repo configured, and downgraded a dependency the same session had just pinned (`motion` 14 → 12). Each add is not an install but a merge: move the file, realign `package.json`, and read what the bit drags in — the `SplitText` bit entered with `gsap` and two `@hugeicons` packages behind its back, which is what forced the one-runtime rewrite (ADR 009, [`components.json`](../packages/ui/components.json)).


**Every list endpoint costs exactly 2 round trips, and that is now the floor, not a coincidence.** Measured on `main` with the query ledger (`apps/api/test/query-budgets.test.ts`) when the budgets were first pinned: `GET /matches` (empty and seeded), `/tournaments`, `/sports`, `/venues`, `/clubs`, `/teams`, `/players` — all 2. The count is not data-dependent plus one free `count(*)`: it is the `{ items, total }` envelope's own shape, two selects (`Promise.all`'d, still two round trips). Any row moving off 2 is the first real conversation about the envelope's cost, with the number already named.

## Measuring

**A test that builds its own fixture with `Date.now()` can lie about which side misbehaved.** The error-contract test initially reported the duplicate-club 409 as missing: the two `POST /clubs` calls each interpolated `Date.now()` into the name, and within the same millisecond the names differed by nothing or by a millisecond at the clock's whim — the first red run read as "the service does not enforce uniqueness", when `createClub`'s conflict check had never been touched. The fix is the shape the budget rows already use: capture the constant once above the calls, so the assertion exercises the case it names, not the clock.

**A component can look right in the diff and wrong in the browser — render its value into the DOM to see why.** The admin sidebar's "the active group reopens by itself" never fired, and reading the comparison said it should: `item.to === matches.at(-1)?.pathname`. Printing the value the component actually computed (`data-debug-path` for one probe run, removed after) answered in a line — `useMatches()` hands the pathname with a trailing slash (`/admin/venues/`), so equality against the nav's `/admin/venues` is false for every item, on every load. The fix normalizes the slash and matches the section by prefix (`/admin/venues/xyz` keeps the group open). "It looks like it should work" is a hypothesis; a value in the DOM is a measurement.

**A first-run experience is only measurable against an empty world, and that world must not be the developer's.** The guide for "create your first tournament" is a branch that needs zero rows, while the dev database had data — and deleting it would have destroyed the only environment with hand-made state. The instrument was a second, disposable world: `sports_platform_test` truncated, a second API on `PORT=4100` against it, a second Vite dev server on `3100` with `VITE_API_URL` pointing at that API, and a probe super_admin inserted straight into the test database. The screenshots of the dashboard, the empty list and the create-then-land-on-the-ficha flow are how the redirect was confirmed rather than merely written. Cheap, because both databases are built by the same `db:push`; worth it, because a branch nobody can look at is a branch nobody has checked.

## Health
**Biome suppressions inside JSX children do not anchor where the rule lives — a scoped override beats a whack-a-mole of comments.** `noArrayIndexKey`'s diagnostics for the vendored react-bits engines sit on the `.map` callback and its `key={index}` attributes, positions where `// biome-ignore` inside JSX children is literally text (`noCommentText`) and element-level comments fix only the a11y half. After three comment shapes refused to stick, the honest shape was an override in `biome.json` setting `noArrayIndexKey: "warn"` for `packages/ui/src/components/bits/**` alone — the engines identify rows positionally by design, the docs say so (ADR 009), and the rule stays strict everywhere else ([ADR 009](./adr/009-react-bits-comes-in-vendored-on-one-runtime-in-tokens.md)).


**A gate that is never run is not a gate — it is a script people believe in.** The root `check-types` entry called `turbo run check-types`, and Turbo's task is named `typecheck`: the type gate had been red-on-name from wherever it was introduced, invisible because nothing at the root ran it until it was walked as part of writing the working brief. The same indirection hid a second layer: two workspaces ran `tsc` without declaring `typescript` and passed through a hoisted binary they did not ask for. Both are one-line honest fixes (point the root script at the real task; declare the dependency where it runs), and the lesson compiles to a habit: every command the brief tells an agent to trust is run once, on `main`, before it becomes an instruction.

**A local gate lives inside an idle container, and an idle container dies.** Hours after a green suite, the same suite failed with `connection refused` on every seed: the Postgres podman container had exited (host restart at some point) and nobody was told — the gate was fat, the environment under it was not. CI's service container exists exactly because of this failure mode; locally, the response to "every test failing to connect at once" is `podman ps` first, `bun test` second.

**The gate found a suite nobody had counted.** The first full gate run failed in `@sports/api-client`: its live E2E suite had all along run under the root `test` task without its own test-environment preload, reaching the database with whatever ambient credentials the machine had. Adding it to the gate is why it was found; the fix (one buried `bunfig.toml` preload borrowed from `apps/api`, plus Turbo `^test` ordering so the two suites sharing one database run in sequence) took minutes after it was visible.

**A scan's first run catches the case its author believed absent.** The `web-fetch` scan was added while a grep said `apps/web/src` had zero raw network calls, and its first run went red on `apps/web/src/lib/api.ts`: the 401 handler refreshed the token with a raw `fetch`, its own URL and JSON body beside the treaty it configures. The reason the call avoided the client is structural — the refresh cannot ride the client whose `onResponse` hook fires `onUnauthorized` on 401, or the refresh's own 401 re-fires the handler with the same dangling `refreshToken` and the cycle nests between two awaits. The repair is a bare client (`createApiClient` without `getToken`/`onUnauthorized`) carrying `auth.refresh.post` through the typed treaty — no exception row in the scan is warranted, the contract kept its single door (ADR 003, [`scripts/checks.ts`](../scripts/checks.ts)).

**`t.Intersect` is not a response-schema composition in Elysia — one `t.Object` with the derived schema's `properties` spread in is.** The matches-with-teams contract was first written as `t.Intersect([selectMatchSchema, t.Object({ homeTeam, awayTeam })])` and passed sporadically: a minimal probe suite got 200 with the full payload while the same call inside `matches.test.ts` and `rbac.test.ts` answered 400 `Unexpected property: /homeTeam` with `Could not create expected value — String types with formats must specify a default value`. The refusal to compile allOf left the validator on the first branch alone, rejecting `homeTeam` as additional — and the nondeterminism (passing in isolation) is what makes it expensive to catch by hand: only a suite that runs every file together pinned it. The flat `t.Object({ ...selectMatchSchema.properties, homeTeam: ... })` compiles deterministically; the nested-relation precedent is `routes/standings.ts` (`{ standing, team }`), which never needed an intersection ([`packages/schemas/src/matches.ts`](../packages/schemas/src/matches.ts)).
**The typed validator turbo-charges the tax to every Link in the app.** Declaring `validateSearch` on the seven admin list routes turned `search` into a mandatory prop for any `<Link to="/admin/…">` in the codebase: a dozen back-links that nothing to do with pagination went red on `MakeRequiredSearchParams`. The repo's existing idiom — the parent page carries the params in `Link search={{ … }}` and the detail page reads them by cast (`Route.useSearch() as {...}`) — is what stays; validation happens in the shared normalizer (`lib/admin-list.ts`), not in the route registration. Second finding in the same patch: `navigate({ search: reducer })` without `to` does not type (`ParamsReducerFn` resolves a generic where search is `string`); the plain-object replacement `navigate({ to: <path>, search: { ...search, ...patch } })` does, and it is explicit about the cost (replaces the whole object — hence the normalizer preserves every domain key such as `clubId`).
